# QRREC V6：RaptorQ 标准 QR 高速版

V6 是新的正式高速实验版本。此前的音频光学方案仅保留在 `V6_AUDIO_OPTICAL_PLAN.md` 作为技术预研，不再作为产品版本实施。

## 数据链路

`原文件 → 可选 deflate → RaptorQ → CRC32C → 1/2/4 个标准 QR → ZXing 多码扫描 → RaptorQ 重建 → 解压 → 原文件`

默认参数为 V30-L、4 QR、30 FPS、20% repair、Balanced 调度。每个文件还会
增加独立的 `QV6` 版本封装、原始长度和 SHA-256，避免其他 RaptorQR 码流被
V6 误接收，并在重建后校验完整文件。

## 统一速率口径

V6 对外展示的主速率定义为：

`原始文件大小 ÷（文件重建解压完成时间 - 第一个有效唯一数据包时间）`

它排除打开页面、授权相机、举起手机、初始对焦等用户操作时间，但包含有效传输期间的漏扫、重复包、修复包、重建和解压，因此代表当前光学链路在一次完整文件传输中的最高可持续平均速率。

页面还显示“唯一载荷接收率”作为诊断指标；它不能代替主速率。

## 本地运行

```bash
npm run dev:sender:v6
npm run dev:receiver:v6
```

## 手机局域网访问

先构建并启动统一的 HTTPS 预览服务器：

```bash
npm run build:v6
npm run preview:v6:lan
```

手机与电脑必须连接同一个 Wi-Fi，然后用终端显示的 `Network` 地址访问，
不能使用 `127.0.0.1` 或 `localhost`。例如：

```text
https://172.17.43.114:4176/
```

首次访问需要在浏览器的自签名证书警告页选择继续访问。若手机浏览器仍不把
自签名地址视为安全上下文，摄像头权限可能被系统拒绝；此时需要在手机上信任
本地开发证书，或改用受信任的 HTTPS 环境。页面样式和普通访问不受影响。

## 构建

```bash
npm run build:v6
```

构建产物位于 `release/web-receiver/v6/`。本版本默认只做本地构建和预览，不自动部署。
