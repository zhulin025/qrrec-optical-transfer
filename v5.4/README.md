# QRREC V5.4：光学条件优化版

V5.4 基于 V5.3，不改变 libcimbar/Wirehair 码流，也继续使用 Zstandard 22 级压缩。它同时升级网页发送端和原生 iOS 接收界面；App 仍保留原 bundle identifier，可覆盖升级已有 V5.1 安装。

## 本版实验点

- **无视觉遮挡**：右上角结束按钮在 2.5 秒后自动隐藏，不再长期覆盖光码码元。
- **92% 安全取景**：光码使用短边的 92%，四周留下黑色安全区，降低轻微晃动导致四角被裁切的概率。
- **黑色外围**：减少整屏白色造成的泛光、反射和自动曝光波动；光码运行层内部仍保留必要白底。
- **首帧校准**：第一张有效数据帧额外保持约 1 秒，让接收端先完成定位、对焦和曝光；重复帧仍是合法喷泉数据。
- **边缘退出**：控制按钮隐藏后，点击光码外的黑色安全区即可结束传输；退出系统全屏也会结束。
- **最高压缩**：发送端继续使用 zstd 22，接收完成后自动解压并恢复原文件名。
- **完整相机预览**：接收端由裁切铺满改为等比例完整显示，用户看到的范围与解码器处理的完整画面一致。
- **动态最佳区域**：辅助框每 0.5 秒综合有效解码 FPS、成功帧比例和定位缓存命中率更新；质量提高时平滑放大并变绿，质量下降时缩小并提示继续调整。
- **正方形识别裁剪**：预览和 C++ 解码器都只使用相机中央正方形区域，减少笔记本边框、键盘和环境背景对定位搜索的干扰。
- **自动保持提示**：连续 1 秒达到接收速率 100 KB/s，或有效解码达到 14 FPS，任一条件满足即可让辅助框高亮变绿，并显示“当前取景位置速度最优，请保持当前位置，不要再调整”。未定位比例保留为诊断指标，不再作为变绿的硬门槛。进入绿色状态后，只有速率持续低于 70 KB/s 且有效解码持续低于 10 FPS 才会逐步退出，避免短暂波动诱导用户重新调整。
- **媒体完成态**：接收到图片后直接展示，接收到视频后提供原生播放器；图片和视频的“保存到相册”按钮直接写入系统照片库，不再弹出分享面板。普通文档仍通过“导出”打开系统分享面板。
- **结果替换取景器**：图片或视频接收完成后，直接占用原来的整个正方形识别区域；相机光码画面立即退出，不再同时保留小媒体预览和无用的取景画面。
- **纯离线权限**：移除历史遗留的 `NSAllowsLocalNetworking` 配置；V5.4 原生接收端没有 URLSession、WebView、本地服务器或网络框架调用。

## 使用与构建

```bash
npm run dev:sender:v54
npm run build:sender:v54
```

- 本地开发入口：Vite 输出的本地地址
- 构建产物：`release/web-receiver/v5.4/send/`
- 接收端工程：`v5.1/ios/OpticalReceiverV51/`（沿用 bundle identifier，以 V5.4 版本覆盖升级）
- 发送端和 App 必须选择相同的 B/Bm/Bu/4C 模式

## A/B 验证

建议用同一文件、同一发送屏幕、同一台 iPhone，分别测试 V5.3 与 V5.4。至少记录有效解码 FPS、接收速率、未定位帧、定位缓存命中率和端到端完成时间。V5.4 默认继续使用已验证较好的 B 模式与 20 FPS；Bm 模式此前在 V5.2 真机测试中未能正常接收。
