# QRREC V5.3：最高强度压缩传输

V5.3 在 V5.2 全屏发送模式上增加发送前无损压缩，使用当前 libcimbar 内置 Zstandard 所支持的最高等级 **22**。接收端在喷泉码文件完整重建后，自动解压并恢复原文件名。

## 数据链路

`原文件 → zstd 22 级压缩 → Wirehair 喷泉码 → 彩色光码 → 原生接收器重建 → zstd 解压 → 原文件`

- 发送端：`npm run dev:sender:v53`
- 生产构建：`npm run build:sender:v53`
- 构建产物：`release/web-receiver/v5.3/send/`
- 接收端：协议与 QRREC V5.1 原生 iOS App 兼容；其 C++ 接收链路已在文件完整后调用 `cimbard_decompress_read` 解压并保存。

## 速度边界

V5.3 提高的是“有效文件吞吐量”，不会提高光码本身每秒承载的压缩字节数。例如文件压缩到原来的 25%，同样的光学链路理论上只需发送约四分之一的数据。

收益取决于文件内容：

- 文本、JSON、CSV、日志、源码、未压缩位图：通常收益明显。
- PDF、Office 文档：视内部资源而定，可能有中等或很小收益。
- JPEG/HEIC、MP4、MP3、ZIP/7z：本身已经压缩，通常几乎没有收益，甚至可能略微变大。

22 级以压缩率优先，发送启动等待和内存/CPU 消耗会高于 V5.1/V5.2。实际是否更快，应以“选择文件到接收端可保存”的端到端总时间为准。
